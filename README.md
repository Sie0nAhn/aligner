# ALIGHNER — Maze UT용 모바일 웹 프로토타입

Figma 시안(`web_프렙_디자인 작업방`, node `424-2827`)의 온보딩 ~ 완료 셀프체크 전 구간을 모바일 웹으로 구현했습니다.
사진·근육 맵 등 이미지 에셋은 Figma 원본에서 그대로 추출했습니다.

자세 사진과 동작 영상은 **YMove Exercise API**에서 실시간으로 받아옵니다.

```
alighner/
├─ index.html                    ← 앱 전체 (HTML+CSS+JS 단일 파일)
├─ api/ymove.js                  ← YMove 프록시 (Vercel용)
├─ netlify/functions/ymove.js    ← YMove 프록시 (Netlify용)
├─ netlify.toml                  ← Netlify 함수 경로 설정
├─ dev-server.js                 ← 로컬 테스트용 (배포에는 불필요)
├─ assets/                       ← Figma에서 추출한 이미지 (API 실패 시 폴백)
│  ├─ silhouette.png       인체 실루엣 (스플래시·분석·부위선택)
│  ├─ pose_camel_cut.png   낙타자세 누끼 (코스 카드)
│  ├─ pose_camel_photo.jpg 낙타자세 원본 사진 (첫 코스 카드)
│  ├─ pose_catcow.jpg      캣카우 가이드 이미지
│  ├─ video_still.jpg      세션 플레이어 폴백 스틸
│  └─ muscle_{chest,core,waist,pelvis}.png  부위별 근육 하이라이트
└─ _figma_raw/                   ← Figma 원본 (백업, 배포 시 제외 가능)
```

## 1. 화면 ↔ URL 대응표 (Maze 미션 목표 설정용)

화면이 바뀔 때마다 주소가 `?s=<화면id>` 로 바뀝니다.
Maze Website Test에서 **미션 성공 조건을 이 URL로 지정**하면 됩니다.

| id | 화면 | UT 설계서 미션 |
|---|---|---|
| `splash` | 로그인 (카카오) | M1 시작 |
| `sport` | 현재 어떤 운동을 하고 있나요 | M1 |
| `duration` | 운동을 하신지 얼마나 됐나요 | M1 |
| `body` | 키와 몸무게 | M1 |
| `easy` | 평소 쉬웠던 자세 | M1 |
| `hard` | 특히 어려웠던 자세 | M1 |
| `analysis` | 등·골반 근육이 약한 것으로 분석돼요 | **M1 목표** |
| `focus` | 강화하고 싶은 부위 선택 | M2 |
| `ready` | 첫 코스가 준비 됐어요 | **M2 목표** |
| `home` | 홈 (오늘의 코스) | M3 시작 / M6 시작 |
| `course` | 데일리 루틴 — 코스 개요 | **M3 목표** |
| `guide` | 캣카우 동작 가이드 | M4 |
| `player` | 세션 플레이어 | **M4 목표** / M5 시작 |
| `rest` | 휴식 타이머 | M5 |
| `quit` | 운동을 그만둘까요 | M5 |
| `complete` | 완료 셀프체크 4문항 | M5 |
| `saved` | 기록 저장 완료 | **M5 목표** |
| `challenges` | 자세 도전 현황 | **M6 목표** |

미션 시작 화면도 URL로 지정할 수 있습니다. 예를 들어 M3는 시작 URL을 `.../index.html?s=home`, 목표를 `?s=course` 로 잡으면 됩니다.

## 2. YMove API 연결 — ⚠️ 먼저 읽어주세요

### 키는 절대 HTML에 넣지 않습니다

YMove 공식 문서에 이렇게 적혀 있습니다.

> **Never expose your API key in client-side code.** Always call the YMove API from your backend and proxy the video URLs to your frontend.

그래서 `index.html`에는 키가 없습니다. 대신 **서버리스 프록시 함수**(`api/ymove.js` / `netlify/functions/ymove.js`)가 키를 들고 API를 호출하고, 브라우저에는 이미 서명이 끝난 임시 영상·썸네일 URL만 내려갑니다. 프록시를 거치지 않으면 배포된 페이지 소스에서 누구나 키를 꺼내 쓸 수 있습니다.

**키 설정 위치 (코드 아님, 대시보드 환경변수)**

- Netlify: Site settings → Environment variables → `YMOVE_API_KEY`
- Vercel: Project → Settings → Environment Variables → `YMOVE_API_KEY`

**지금 쓰는 키는 UT가 끝나면 재발급하세요.** 대화창에 한 번 붙여넣은 키라 유출 위험이 있습니다.

### 확인해야 할 계정 조건 (2026-07-31 기준, `/usage` 응답)

| 항목 | 현재 값 | 의미 |
|---|---|---|
| 플랜 | `basic` / **trial** | 체험 상태 |
| **체험 종료** | **2026-08-04** | **이 날짜가 지나면 영상이 끊깁니다. UT 일정이 이후라면 결제 필요** |
| 영상 워터마크 | 있음 | Trial·Starter는 우하단에 `your move` 로고. Pro 이상부터 제거 |
| 월 고유 운동 수 | 100개 중 14개 사용 | 이 프로토타입이 쓰는 자세는 14개라 여유 있음 |
| 영상 분량 | 10,000분 | 참가자 20명이 다 봐도 한참 남습니다 |

### 동작 방식

- 페이지가 열리면 프록시를 **한 번** 호출해 14개 자세의 썸네일·영상 URL을 받습니다 (서버에서 30분 캐시)
- YMove 영상 URL은 **48시간 뒤 만료**됩니다. 그래서 URL을 파일로 저장하지 않고 매번 API에서 새로 받습니다
- 재생이 실패하면 `?refresh=1` 로 프록시에 한 번 재요청하고, 그래도 안 되면 조용히 시안 스틸컷으로 폴백합니다 (화면이 검게 죽지 않음)
- **프록시가 없어도 앱은 동작합니다.** `index.html`을 그냥 더블클릭해 열면 Figma 시안 이미지로 폴백됩니다

### 자세 ↔ YMove slug 매핑

| 앱 | YMove slug | | 앱 | YMove slug |
|---|---|---|---|---|
| 낙타자세 | `camel-pose` | | 캣카우 | `cat-cow-pose` |
| 휠 | `wheel-pose` | | 다운독 | `downward-dog` |
| 활자세 | `bow-pose` | | 테이블탑 밸런스 | `tiger-pose-right` |
| 보트자세 | `boat-pose` | | 플랭크 트랜지션 | `plank-pose` |
| 사이드플랭크 | `side-plank-pose-right` | | 낮은 런지 | `low-lunge-right` |
| 반보트 | `half-boat-pose` | | 브릿지 | `bridge-pose` |
| 말라사나 | `garland-pose` | | 파이어로그 | `fire-log-pose-right` |

자세를 바꾸려면 `index.html`의 `POSE_SLUG`와 프록시 파일의 `SLUGS` 배열 **양쪽 다** 고쳐야 합니다(프록시의 허용 목록이 아니면 안 내려갑니다).

## 3. 올리는 방법

**Netlify (권장 — 함수까지 한 번에)**

1. [app.netlify.com](https://app.netlify.com) → Add new site → Deploy manually → `alighner` 폴더를 끌어다 놓기
2. Site settings → Environment variables → `YMOVE_API_KEY` 추가
3. Deploys → Trigger deploy (환경변수 적용을 위해 한 번 더 배포)

**Vercel**

1. 폴더를 저장소에 올리고 Vercel에서 Import (또는 `vercel deploy`)
2. Settings → Environment Variables → `YMOVE_API_KEY` 추가 후 재배포

**GitHub Pages는 쓰지 마세요.** 서버리스 함수를 실행할 수 없어 API 연동이 동작하지 않습니다(시안 이미지로만 폴백됩니다).

**로컬에서 확인**

```bash
cd alighner
YMOVE_API_KEY=ym_... node dev-server.js
# → http://localhost:8077
```

쿼리 파라미터(`?s=...`) 방식이라 새로고침해도 404가 나지 않습니다.
배포 후 Maze → Create maze → **Website test** → 위 URL 입력 순서로 연결하세요.

## 4. 구현된 인터랙션

- **온보딩**: 종목 단일 선택 / 기간 선택 / 키·몸무게 **실제 입력** / 자세 최대 4개 다중 선택(n/4 카운터) — 선택 전까지 `다음` 비활성
- **부위 선택**: `등` 탭 → 하·중·상 아코디언 열림, 선택 시 실루엣 핫스팟 점등
- **홈**: 코스 카드 → 코스 개요, `전체보기` → 자세 도전 현황
- **동작 가이드**: 가슴·코어·허리·골반 탭 전환 시 근육 맵과 핵심 동작 문구가 함께 바뀜
- **세션 플레이어**: **YMove 실제 동작 영상 재생**(세로 9:16, 무음·반복), 실제 카운트다운, 재생/일시정지, 자막 시간대별 전환, `다음` → 휴식 타이머(30초 실제 카운트, ±10초) → 2번째 동작 → 완료 셀프체크
  - 영상은 `muted` + `loop` 입니다. 요가 클립이 약 30초라 세트 시간(3분/2분) 동안 반복 재생됩니다
  - 무음인 이유: 모바일 브라우저는 소리 있는 영상의 자동재생을 막습니다. 시안에도 볼륨 UI가 없어 음성 큐는 자막으로만 전달됩니다
- **X 버튼**: `운동을 그만둘까요?` 시트, 완료 동작 수 표시, 이어서 하기 / 그만두기
- **완료 셀프체크**: 4문항 토글, 체크 수가 기록 저장 화면에 반영
- **뒤로가기**: 브라우저 뒤로가기 정상 동작 (참가자가 스와이프해도 깨지지 않음)
- **`마이` 탭**: 시안에 화면이 없어 **의도적으로 미연결** — 이 클릭은 Maze에서 misclick으로 잡힙니다

## 5. 시안과 다르게 만든 부분 (의도적 결정)

결과 해석에 영향을 주는 항목이라 먼저 확인해 주세요.

| 항목 | 시안 | 구현 | 이유 |
|---|---|---|---|
| 상단 상태바 (9:41, 배터리) | 있음 | **없음** | 실제 폰에서 테스트하면 진짜 상태바와 겹쳐 보입니다 |
| 홈 `자세 도전 현황` 카드 캡션 | 3장 모두 "완료" | 자세 이름 + `3/4` `2/4` `1/4` | 시안 값이 자세 도전 현황 화면(3/4, 2/4, 1/4)과 어긋나 있어, 그대로 두면 M6에서 데이터 불일치가 사용성 문제로 오독됩니다 |
| 코스 동작 리스트 | 4개 노출 | 6개 | 카드에 "6개 운동"이라 적혀 있어 개수를 맞췄습니다. 5·6번은 `본운동`으로 표기 |
| 동작 가이드 핵심 동작 문구 | `가슴` 탭 1개만 존재 | 코어·허리·골반 3개는 **제가 작성** | 탭이 동작해야 M4 검증이 가능. UT 전에 실제 카피로 교체 권장 |
| 음성 큐 자막 | 첫 줄만 존재 | 나머지는 **제가 작성** | 위와 동일 |
| 강화 부위 선택 `다음` 버튼 | 없음 | 있음 (선택 후 활성) | 버튼이 없으면 다음 화면으로 넘어갈 수 없습니다 |
| 기록 저장 완료 화면 | 없음 | 새로 만듦 | M5의 목표 화면(성공 판정 지점)이 필요합니다 |
| 자세 사진 (그리드·리스트) | 대부분 빈 플레이스홀더 | YMove 실제 사진 9종 + 6종 | 참가자가 자세를 보고 골라야 M1이 성립합니다 |
| 세션 플레이어 영상 | 정지 이미지 | YMove 실제 동작 영상 | 재생·일시정지 조작성이 M5의 검증 대상입니다 |
| 운동 종목 그리드 (발레·수영·태권도…) | 빈 플레이스홀더 | **그대로 빈 플레이스홀더** | YMove는 운동 DB라 종목 사진이 없습니다. 시안도 요가만 채워져 있어 동일하게 유지 |

**시안 그대로 남겨둔 것**: 완료 셀프체크 2번 문항 `골반이 앞으로 밀었나요?` 는 어색한 문장이지만 수정하지 않았습니다. 이 문구가 참가자에게 어떻게 읽히는지가 M5의 검증 대상이기 때문입니다.
